# Dashboard settings

Operator Console → System → **Settings** shows every mm-core setting. Each carries a badge:

| Badge | Meaning |
|---|---|
| ⚡ live | Takes effect when you press **Save** — no restart. |
| ↻ restart | Saved as *pending*. The amber banner offers **Apply & restart**: the API is unavailable for about 5 s; LiveKit and mm-switch keep carrying media, so viewers keep watching. |
| 🔒 read-only | Bootstrap values (database URL, JWT signing key, admin token, listen addresses). Change them in `.env` and restart. |
| ↔ host-coupled | The same value must also be set in another service (Synapse, LiveKit, coturn, mm-switch, Traefik, Prometheus). Read-only for now. |

## Where values come from

`defaults → config file → .env → dashboard`. On the first start of this version mm-core
copies the current file/.env value of every editable setting into the database, so
nothing changes on upgrade. From then on **the dashboard value wins**: mm-core logs one
warning listing `.env` variables it now ignores, and the dashboard marks them.

## Secrets

Secret settings (S3 keys, Stripe keys, LNbits keys, the server-request webhook) are
encrypted at rest with `MM_SETTINGS_ENCRYPTION_KEY` (generated by the installer, stored in
`.env.secrets`). The dashboard never displays them — only "Set · last changed …" and
**Replace**. Without the key, secrets stay `.env`-managed and read-only in the dashboard.
Losing the key means re-entering those secrets; every other setting survives.

Rotate the key with `mmctl rotate MM_SETTINGS_ENCRYPTION_KEY` (two mm-core recreates;
secrets are re-encrypted at startup).

## Safe mode

- **Automatic:** if a stored value is invalid (for example written by a newer version),
  mm-core starts from file + `.env` only and the dashboard shows a red banner naming the
  setting. Fix it in the dashboard, then **Apply & restart**.
- **Break-glass:** set `MM_SETTINGS_SAFE_MODE=1` in `.env` and recreate mm-core to ignore
  every dashboard value. Remove it and recreate again to return to normal.

## Restarts

"Apply & restart" makes mm-core exit through its graceful shutdown; the restart policy
brings it back (`restart: unless-stopped` in compose, `Always` on Kubernetes). With
several instances, each restarts after a random 0–10 s delay. A process started by hand
(`cargo run`, a systemd unit with `Restart=on-failure`) simply exits — start it again.
