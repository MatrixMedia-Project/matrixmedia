# Dashboard settings

Operator Console → System → **Settings** shows every mm-core setting. Each carries a badge:

| Badge | Meaning |
|---|---|
| ⚡ live | Takes effect when you press **Save** — no restart. |
| ↻ restart | Saved as *pending*. The amber banner offers **Apply & restart**: the API is unavailable for about 5 s; LiveKit and mm-switch keep carrying media, so viewers keep watching. |
| 🔒 read-only | Bootstrap values (database URL, JWT signing key, admin token, listen addresses). Change them in `.env` and restart. |
| ↔ host-coupled | The same value must also be set in another service (Synapse, LiveKit, coturn, mm-switch, Traefik, Prometheus). Read-only for now. |

## Where values come from

`defaults → config file → .env → dashboard`. On the first start of this version mm-core
copies the current file/.env value of every editable setting into the database, so
nothing changes on upgrade. From then on **the dashboard value wins**: mm-core logs one
warning listing `.env` variables it now ignores, and the dashboard marks them.

After that first start, `.env` is only two things for an editable setting:

- **the first-boot seed:** a value mm-core has not stored yet (a secret that was still
  empty, a setting added by a later release) is picked up from `.env` at the next start;
- **the fallback when mm-core cannot use the stored value:** in safe mode, mm-core runs
  from file + `.env` alone, whether you turned it on (the break-glass
  `MM_SETTINGS_SAFE_MODE=1`) or it started that way because a stored value is invalid (see
  [Safe mode](#safe-mode)); and a stored secret it cannot decrypt keeps its `.env` value
  (see [Secrets](#secrets)).

So these are done in Operator Console → System → **Settings** → Monetization, not in
`.env`: turning payments on, changing the platform fee, rotating the Stripe or LNbits
keys, and going live (the `sk_test_…` secret key replaced by the `sk_live_…` one, and the
webhook signing secret replaced by the `whsec_…` secret of the live-mode endpoint).
Change the values, press **Save**, then **Apply & restart** (payments on/off and the
keys are restart settings; the fee and donations apply on Save). Editing them in `.env`
changes nothing once mm-core has stored them. Read-only (🔒) and host-coupled (↔)
settings stay in `.env` as before.

## Secrets

Secret settings (S3 keys, Stripe keys, LNbits keys, the server-request webhook) are
encrypted at rest with `MM_SETTINGS_ENCRYPTION_KEY` (generated by the installer, stored in
`.env.secrets`). The dashboard never displays them — only "Set · last changed …" and
**Replace**. Without the key, secrets stay `.env`-managed and read-only in the dashboard.
Losing the key means re-entering those secrets; every other setting survives. Until then,
a stored secret mm-core cannot decrypt (the key is missing, wrong or unusable) keeps its
`.env` value, and the Settings page lists it as not in use.

To rotate a Stripe or LNbits key, rotate it at the provider, then press **Replace**,
enter the new value, **Save**, and **Apply & restart**. A new value in `.env` is ignored
once the dashboard holds the secret, so until it is replaced here mm-core keeps using the
old, revoked key.

Rotate the encryption key itself with `mmctl rotate MM_SETTINGS_ENCRYPTION_KEY` (two
mm-core recreates; secrets are re-encrypted at startup). It finishes only when mm-core
runs its stored settings (not in safe mode) and reports every secret re-encrypted, so
remove `MM_SETTINGS_SAFE_MODE` from `.env` before rotating. If a rotation stops
part-way, run the same command again: it resumes instead of generating another key. To
roll a rotation back, do **not** restore the phase-0 `.env.secrets` backup, which does
not hold the new key; follow the reverse procedure in the `MM_SETTINGS_ENCRYPTION_KEY`
entry of [rotation-runbooks.md](rotation-runbooks.md).

## Safe mode

- **Automatic:** if a stored value is invalid (for example written by a newer version),
  mm-core starts from file + `.env` only and the dashboard shows a red banner naming the
  setting. Fix it in the dashboard, then **Apply & restart**.
- **Break-glass:** set `MM_SETTINGS_SAFE_MODE=1` in `.env` and recreate mm-core to ignore
  every dashboard value. Remove it and recreate again to return to normal.

## Restarts

"Apply & restart" makes mm-core exit through its graceful shutdown; the restart policy
brings it back (`restart: unless-stopped` in compose, `Always` on Kubernetes). With
several instances, each restarts after a random 0–10 s delay. A process started by hand
(`cargo run`, a systemd unit with `Restart=on-failure`) simply exits — start it again.

## Upgrade notes

### LNbits keys stored as `placeholder`

Earlier compose templates passed the literal `placeholder` as `MM_LNBITS_INVOICE_KEY`
and `MM_LNBITS_ADMIN_KEY` when `.env` did not set them. The current template passes them
empty, which means "not configured". An install that started mm-core with
`MM_SETTINGS_ENCRYPTION_KEY` under the old template stored that literal as both LNbits
keys, so Settings → Monetization shows them as *Set* although nobody entered them.
Refreshing `docker-compose.yml` (re-run `install.sh`) does not change what is stored.

If you never set LNbits keys yourself (in `.env` or in the dashboard): in Operator
Console → System → **Settings** → Monetization, press **Clear** on
`monetization.lnbits_invoice_key` and `monetization.lnbits_admin_key`, **Save**, then
**Apply & restart**. If you did set them, they hold your own keys and nothing needs
doing.
