# Building the MatrixMedia JVM SDK

This is a developer walkthrough for cross-compiling the FFI crate, generating
the Kotlin bindings, and producing the publishable fat `.jar`.

> **Status:** scaffold only. Several steps below are TODOs marked in code.
> Treat this document as the target spec for the eventual implementation.

## 1. Prerequisites

### Toolchains

```bash
# Rust + targets
rustup toolchain install stable
rustup target add x86_64-pc-windows-msvc
rustup target add x86_64-unknown-linux-gnu
rustup target add aarch64-unknown-linux-gnu
# (later) rustup target add x86_64-apple-darwin aarch64-apple-darwin

# Zig — backend for cargo-zigbuild's cross linker
brew install zig                   # macOS
# or: snap install zig --classic   # Linux

# cargo-zigbuild — wraps `cargo build` and routes the linker to zig
cargo install cargo-zigbuild

# UniFFI bindgen for Kotlin (CLI) — installed once per dev box.
cargo install uniffi-bindgen-cli
# Note: matrix-rust-sdk uses its own `uniffi-bindgen-kotlin` fork. The
# eventual Rust dev should pick whichever one matches the proc-macro vs
# .udl approach we settle on.
```

### JVM toolchain

- JDK 17 (Temurin recommended)
- Gradle wrapper (will be regenerated by the dev when first running
  `gradle wrapper` — not committed yet to keep the scaffold lean)

## 2. Wire the matrix-rust-sdk dependency

Edit `ffi/Cargo.toml` and uncomment / pin the `matrix-sdk-ffi` line. Two
patterns:

```toml
# Option A — pin to upstream tag (preferred for reproducibility)
matrix-sdk-ffi = {
  git = "https://github.com/matrix-org/matrix-rust-sdk",
  tag = "matrix-sdk-ffi-0.X.Y"
}

# Option B — local fork (when patches are required)
matrix-sdk-ffi = { path = "../../../../matrix-rust-sdk/bindings/matrix-sdk-ffi" }
```

The Mages project (AGPL — read for reference, do **not** vendor source)
demonstrates option B with a local fork. Their `core/` crate similarly
re-exports the upstream FFI surface and adds a thin layer of project-specific
helpers; the corresponding Gradle build glues the resulting `.so`/`.dll`
into a JAR via `Exec` tasks. The same shape applies here.

## 3. Cross-build the native libraries

```bash
cd sdks/jvm
./scripts/build-all.sh                  # all targets
./scripts/build-all.sh linux-x64        # one target
```

Artifacts land under `sdks/jvm/target/<triple>/release/`:

| Triple                          | Output                                  |
| ------------------------------- | --------------------------------------- |
| `x86_64-pc-windows-msvc`        | `matrix_mm_ffi.dll`                     |
| `x86_64-unknown-linux-gnu`      | `libmatrix_mm_ffi.so`                   |
| `aarch64-unknown-linux-gnu`     | `libmatrix_mm_ffi.so`                   |

### Common cross-compile gotchas

- **Windows MSVC**: `cargo-zigbuild` needs the MSVC SDK headers. Either set
  up [`xwin`](https://github.com/Jake-Shadle/xwin) or install Visual Studio
  Build Tools and point `LIB`/`INCLUDE` at them.
- **Linux glibc compat**: pin a baseline glibc by appending the version to
  the triple, e.g. `--target x86_64-unknown-linux-gnu.2.17`. This makes the
  resulting `.so` runnable on RHEL/CentOS 7-era hosts.
- **macOS** (when added): set `SDKROOT` and `MACOSX_DEPLOYMENT_TARGET=11.0`.

## 4. Generate the Kotlin bindings

Once `build-all.sh` succeeds, the UniFFI scaffolding is embedded in each
`.so`/`.dll`. Generate the Kotlin shim with:

```bash
uniffi-bindgen-cli generate \
  --library target/x86_64-unknown-linux-gnu/release/libmatrix_mm_ffi.so \
  --language kotlin \
  --out-dir kotlin/build/generated/uniffi/main/kotlin
```

> The Gradle `uniffiBindgenKotlin` task in `kotlin/build.gradle.kts` will
> wrap this call — currently a stub (TODO). Hook it into
> `compileKotlin.dependsOn(...)`.

## 5. Pack the native libraries into the JAR

```bash
./scripts/package-jar.sh
```

This copies each native artifact into
`kotlin/src/main/resources/<jna-resource-prefix>/`, matching JNA's
resource-loading convention:

| OS / Arch              | Resource prefix    |
| ---------------------- | ------------------ |
| Windows x86_64         | `win32-x86-64`     |
| Linux x86_64           | `linux-x86-64`     |
| Linux aarch64          | `linux-aarch64`    |
| macOS x86_64 (planned) | `darwin-x86-64`    |
| macOS aarch64 (planned)| `darwin-aarch64`   |

## 6. Build the JAR

```bash
cd kotlin
./gradlew jar
```

Output: `kotlin/build/libs/matrixmedia-jvm-<version>.jar`

### Verify the JAR contains the natives

```bash
unzip -l kotlin/build/libs/matrixmedia-jvm-*.jar | grep -E '\.(so|dll|dylib)$'
```

You should see one line per supported triple. If any are missing, re-run
`build-all.sh` and `package-jar.sh` for that triple.

## 7. Publish

### Local (development)

```bash
cd kotlin
./gradlew publishToMavenLocal
```

Consume from another local project:

```kotlin
repositories { mavenLocal() }
dependencies { implementation("dev.matrixmedia:matrixmedia-jvm:0.1.0-SNAPSHOT") }
```

## 8. Smoke test

A trivial Kotlin program that exercises the pipeline:

```kotlin
import uniffi.matrix_sdk_ffi.version

fun main() {
    println("matrix-mm-ffi version = ${version()}")
}
```

If that prints the crate version (currently `0.1.0`), the entire
Rust → UniFFI → Kotlin → JNA → JAR chain is working.
